# ds-webui-import

Опциональный конвертер `.xlsx` → ленивый columnar-формат [`ds-webui`](https://github.com/A1eksMa/ds-webui)
(`ds-webui/docs/contract.md`). Подключается к `ds-webui` как git submodule (каталог `import/`)
и полностью опционален: без него `ds-webui` работает как сейчас, без единой новой зависимости
или точки входа в интерфейсе; с ним — на странице «Настройки» появляется кнопка «Импорт».

## Что делает

Пользователь выбирает `.xlsx`-файл (плоская таблица, первый лист, первая строка — заголовки),
указывает в диалоге имя нового источника и какая колонка — ключ (+ необязательное описание).
Конвертер:

1. Разбирает лист через [SheetJS Community Edition](https://sheetjs.com/) (вендорится,
   `vendor/xlsx.full.min.js`, версия `0.20.3`, лицензия Apache-2.0 — см. `vendor/SHEETJS-LICENSE`).
2. Строит файл источника `<Имя>.js` в формате `ds-webui`, тот же контракт, что производит
   `ds-loader` — ключ + каждый показатель как функция, позиционно по строкам.
3. Строит `manifest-<Имя>.js` — фрагмент манифеста с одной записью.
4. Обновляет (или создаёт) `manifest.imports.js` — индекс всех таких фрагментов (можно
   опционально передать уже существующий файл в том же диалоге, чтобы не потерять ранее
   добавленные источники — конвертер сам ничего не помнит между запусками).

Все три файла отдаются обычным скачиванием браузера (`ds-webui`'s `effects.js::download`, тот
же механизм, что у экспорта CSV/XLS) — **никакой записи на диск отсюда и никакого
автоматического добавления источника в текущую сессию** (осознанно: страница должна оставаться
рабочей без File System Access API и без завязки на `http(s)`, то есть без потери поддержки
`file://`). Пользователь сам переносит скачанные файлы в свой каталог данных (`data/` или
любой другой, настраиваемый на «Настройках») и жмёт там «Обновить манифест» — без перезагрузки
страницы.

## Подключение к ds-webui

```
cd ds-webui
git submodule add https://github.com/A1eksMa/ds-webui-import.git import
```

`ds-webui/index.html` уже содержит (опциональные, по тому же паттерну, что и `data/base.js`)
теги для `import/vendor/xlsx.full.min.js` и `import/import.js` — отсутствие каталога `import/`
(submodule не инициализирован) не ошибка, просто кнопки «Импорт» не будет. Полный («full»)
релиз `ds-webui` собирается с инициализированным submodule-ем, «lite» — без него
(`git submodule deinit` / просто не клонировать submodule).

## Лицензия

MIT (см. `LICENSE`) — открыто сейчас, сознательно. Архитектурно изолирован от основного
`ds-webui` именно для того, чтобы при необходимости в будущем разделить продукт на бесплатное
открытое ядро и платную версию с готовыми конвертерами — это решение пока не принято, но
структура репозитория уже позволяет его принять без переделки. Уже опубликованные версии
этого репозитория останутся доступны всем по этой же лицензии независимо от будущих решений
по видимости/лицензии репозитория — это осознанный выбор, не недосмотр.

Вендоренная библиотека (`vendor/xlsx.full.min.js`) — своя отдельная лицензия (Apache-2.0,
`vendor/SHEETJS-LICENSE`), не переиздаётся под MIT, только используется как зависимость.
sha256 текущего вендоренного файла (для проверки целостности при обновлении версии):
`cc015130aa8521e7f088f88898eba949ccdcbfb38df0bd129b44b7273c3a6f41`.

## Тесты

`./run_tests.sh` (`node --test`) — юнит-тесты чистых функций (сериализация источника и
манифеста, разбор листа, слияние индекса фрагментов). DOM-часть (диалог, оркестрация
`importXlsx`) не покрыта автотестами в этом репозитории — проверяется вручную в браузере.
